# 代码说明

## 1 定位

本服务把第5章“失效响应—安全屏障”规则链评价模型封装成一个**无状态的JSON计算服务**：调用方给出一个评价单元（代表断面）的工程资料、计算结果、台账结论和巡检证据，服务返回安全得分、A/B/C等级、主控失效模式、门控原因、指标得分和指标贡献。

服务**做**的事：

- 指标量化、失效模式响应、管理屏障修正、短板约束综合、观测门控和硬约束门控，全部由交付的模型代码完成；
- 对输入做严格校验，把交付代码中会“默认满分”的缺省情况挡在门外（见第4节）；
- 把结果整理成英文字段名的JSON，附带提示信息（warnings）和可追溯信息（模型文件sha256、输入sha256）。

服务**不做**的事：

- 不做渗流有限元计算和边坡稳定计算：渗透比降、安全系数需由调用方（第4章数值模型或设计复核成果）提供；
- 不做无人机图像识别：只接收**已经人工复核确认**的渗漏/管涌事件或调用方汇总好的证据；
- 不存储任何数据：每次请求独立计算，服务端不落盘；
- 不包含随机森林等研究性模型：随机森林只在研究中用于对照分析，不参与等级判定。

## 2 评价原理

计算链与第5章一致，分七步：

1. **二级指标量化**：29项指标分为A工程质量（A1–A9）、B防洪安全（B1–B4）、C渗流安全（C1–C6）、D结构安全（D1–D5）、E运行管理（E1–E5）。连续量按规则打分（如C1：S=100(1−R²)，R=i/i_cr，i_cr=(Gs−1)/(1+e)；D1、D2按安全系数分段线性），定性结论按分档赋分（见参数字典第2节）。
2. **指标→失效模式**：每项指标与五类失效模式的关联强度（0～3）乘以AHP指标权重（一级权重A/B/C/D/E=0.1818/0.1818/0.3636/0.1818/0.0909），归一化得到模式权重和模式内指标权重。模式权重为：漫顶失效0.1726、渗流破坏0.4085、边坡失稳0.2350、冲刷破坏0.0750、穿堤建筑物失效0.1089。
3. **失效模式响应**：模式响应R_k是模式内各指标风险响应（1−得分/100）的加权平均。B1、C1/C4/C5、D1/D2改用物理响应：超高亏欠/规范超高、i/i_cr、安全系数裕度。任一渗流比降比值≥1、任一坡安全系数<1或超高亏欠达到整个超高时，该模式响应直接取1。
4. **管理屏障修正**：E类指标给出屏障能力B_m和信息覆盖度c，修正为R′_k = R_k + λ·c·R_k(1−R_k)(1−B_m)，默认λ=0.5。0与1两端不变，中间风险受管理状况影响最大。
5. **短板约束综合**：ρ = α·max R′_k + (1−α)·Σ w_k R′_k（只对有数据的模式归一化），默认α=0.45；安全得分S=100(1−ρ)。按得分分级：A≥80，40≤B<80，C<40。
6. **观测门控**：巡检证据可把等级上限压到B或C（规则见HTTP接口说明第5节）。
7. **硬约束门控（只降不升）**：

| 条件 | 等级上限 |
|---|---|
| 堤顶高程低于设计洪水位，或超高亏欠≥规范超高的50% | C |
| 超高不足（其他情况） | B |
| C1/C4/C5任一 i/i_cr ≥ 1.0 | C |
| C1/C4/C5任一 0.8 ≤ i/i_cr < 1.0 | B |
| 背水坡FoS < 1.05 / 临水坡FoS < 1.05 | C |
| 背水坡FoS < 1.35 / 临水坡FoS < 1.25 | B |
| D3 = 0（严重冲刷或未加固重大险情） | C |
| D3 ≤ 70 | B |
| A3、B4、C6、D4任一 = 0 | C |
| A3、B4、C6、D4任一 ≤ 60 | B |
| 软基沉降 > 22.5 cm 或沉降差 > 7.5 cm | C |
| 软基沉降 > 15 cm 或沉降差 > 5 cm | B |

**缺失指标**不补值、不当满分：在所属失效模式内按现有指标权重重新归一化；整个模式都缺失时该模式不参加综合。E类全部缺失时不做屏障修正（覆盖度为0）。缺失指标在响应的 `missing_indicators` 和 `warnings` 中列出。

## 3 代码结构

```
levee_eval/
  model/                               交付的模型代码，原样复制，不做任何修改
    safety_evaluation.py               指标量化函数、常数、巡检证据汇总规则
    failure_response_barrier_model.py  失效响应、屏障修正、短板综合、门控；evaluate_section()
    failure_mode_indicator_matrix.json 指标—失效模式关联矩阵
  schema.py    请求字段的唯一定义（类型、单位、范围、枚举、对应指标、内部字段名）和校验器
  engine.py    JSON请求 → 交付模型输入 → evaluate_section() → JSON响应
  openapi.py   由schema生成OpenAPI 3.0文档；内含示例请求
  wsgi.py      HTTP层（标准库WSGI）：路由、鉴权、CORS、错误处理、日志
  server.py    标准库多线程开发服务器
tools/
  build_fixtures.py   重新生成875个合成样本的回归基准
  gen_docs.py         由代码生成参数字典、openapi.json和examples
  reference/          交付的合成样本生成脚本（仅用于生成回归基准）
tests/                单元测试、HTTP测试、875样本回归测试、文档一致性测试
```

服务层对交付代码做了以下**适配**，均不改变交付代码在完整输入上的计算结果（第5节的回归测试逐项证明）：

1. **单评价单元调用**：交付的 `evaluate_section()` 按桩号从全线台账列表（填土质量分段、穿堤建筑物、历史险情）中检索。服务每次只评价一个单元，因此把调用方给出的台账结论构造成只含该单元的列表，内部统一使用桩号“0+000”；调用方的 `section_id` 只原样返回，不参与计算。
2. **C3缺失**：交付的 `score_C3()` 无法表达“没有有效巡检”（传入None会报错）。服务在导入时对其做了一层包装：没有有效巡检时返回None，C3按缺失处理；其余情况原样调用交付函数。
3. **巡检事件汇总**：events模式下，服务调用交付的 `match_uav_leakage_evidence()`，把已确认事件放在同一个虚拟位置（距离0）并标记为人工确认（置信度1.0），评价段长度取 `segment_length_m`。因此密度、位置权重、重复权重、证据等级和门控上限完全按交付规则计算，调用方不需要也不应该传坐标。
4. **缺资料的输入（v1.1）**：交付代码要求两侧抗滑稳定安全系数和冲刷深度必须存在，并把缺省的沉降量当作非软基段计100分。服务包装了 `score_D1`、`score_D2`、`score_D3`、`score_A5`、`slope_response`、`mode_contribution_overrides` 和 `hard_constraint_gate`：输入存在时原样调用交付函数；不存在时对应指标记为缺失，边坡失稳模式只用有数据的指标计算，对应门控不检查并列入 `gates_not_checked`。没有冲刷深度但有未加固的重大险情记录时，D3仍按交付规则计0分。
5. **D3门控文字（v1.1）**：交付代码的D3门控原因只写冲刷深度，即使70分或0分实际来自险情记录（例如冲刷0.40 m、有已加固管涌记录时写“D3冲刷深度=0.40m存在冲刷风险”）。服务把这种情况的文字改写为说明险情记录的版本，得分和等级上限不变。

## 4 服务层强制的输入要求

交付代码为了批量处理方便，在若干字段缺省时会静默取默认值，其中多数会得到满分。作为对外服务，这些缺省会把“资料缺失”伪装成“安全”，因此服务端改为**必须显式给出**：

| 交付代码的缺省行为 | 服务的要求 |
|---|---|
| 未给控制层且无土层表时取Gs=2.70、e=0.85 | `section.control_layer` 与 `section.soil_layers` 至少给一个 |
| 不在填土质量分段内时A2=100 | `records.fill_quality` 必填 |
| 无穿堤建筑物记录时A3=100 | `records.crossing_structure_class` 必填；确无建筑物填“不涉及”（仍按100分，并给出提示） |
| 无历史险情记录时A6=100、D3不扣分 | `records.historical_dangers` 必填，已核查无记录时传 `[]` |
| 堤基类型非C/D时A7=100 | `section.foundation_class` 与 `qualitative.A7` 至少给一个；由堤基类型推定时给出提示 |
| 堤身、接触面比降缺省为0 | `computation.body_gradient`、`contact_gradient` 必填 |
| 给出沉降量但缺沉降差时报TypeError | 给出沉降量时沉降差必填 |
| 无巡检时 `score_C3(None)` 报错 | 未覆盖或过期时 `inspection.coverage="none"`（或不传inspection），C3按缺失处理并给出提示 |
| 缺两侧安全系数或冲刷深度时报错（KeyError） | v1.1起可不填：D1/D2/D3缺失、不做对应门控，并在 `gates_not_checked` 中列出 |
| 未给沉降量时A5=100 | 沉降资料未知时填 `survey.soft_foundation_status="unknown"`，A5缺失、不做沉降门控；不填时仍按非软基段计100分并提示 |

其余定性指标（A4、A8、A9、B2–B4、C2、C6、D4、D5、E1–E5）未给出时按缺失处理，这是交付代码本身的行为，服务保持不变。

## 5 正确性验证

```
python -m unittest discover -s tests -t . -v
```

共24项测试，全部只用标准库：

- **875样本回归**（`tests/test_regression_875.py`）：用交付的合成样本生成脚本（固定随机种子）重建875个样本，转换成API请求后经服务计算，得分、等级、模型原始等级、观测门控后等级、ρ、主控模式、门控原因、屏障能力与覆盖度、五类模式原始与修正响应、29项指标得分、缺失指标**逐项完全相等**于直接调用交付代码的结果；生成基准时还与交付的结果文件 `synthetic_evaluation_results.json` 逐项比对一致。
- **模型文件校验**：三个模型文件的sha256必须等于上表。
- **校验与证据规则**：必填、未知字段、类型、枚举、范围、交叉规则；无巡检时C3缺失；events模式证据等级与门控；aggregated模式；硬约束门控；批量接口单项失败隔离。
- **缺资料输入（v1.1）**：不给安全系数、冲刷深度、沉降资料和巡检时对应指标缺失、门控不检查；只给一侧安全系数；无冲刷深度但有未加固管涌记录时D3=0；D3门控文字改写。
- **HTTP**：各接口、400/401/404/405/413/415/422、API Key、CORS、真实端口收发。
- **文档一致性**：参数字典、openapi.json、examples必须与代码生成结果一致。

## 6 适用范围与限制

- **等级含义**：A/B/C是本研究的评价等级，不等同于SL/Z 679-2015《堤防工程安全评价导则》的一类/二类/三类堤，不能直接替代安全鉴定结论。
- **验证范围**：模型目前只在受控的合成样本上验证过区分能力和计算一致性，尚未用实际堤段的鉴定结论做标定，不能据此宣称对其他堤段或工况的适用性。
- **输入质量决定结果**：服务不检查渗流计算、地勘资料和台账本身是否正确。比降、安全系数应与同一水位工况对应；巡检证据应在有效期内，过期时按 `coverage="none"` 处理。
- **一次一个单元**：每个请求代表一个评价单元（代表断面）。全线评价请按单元逐个调用或使用批量接口，单元划分由调用方负责。
- **巡检事件**：只能传入经人工复核确认的事件；算法候选、误报和未复核的目标不得传入，否则会抬高C3扣分和门控等级。

## 7 版本与变更

- 接口版本 `api_version` 遵循语义化版本：1.x内只做向后兼容的新增（新增可选字段、新增响应字段）；不兼容的变更使用新的路径前缀 `/api/v2`。
- 调用方应忽略不认识的响应字段，以便兼容1.x的后续版本。
- 版本记录：
  - **1.1.0（2026-10-25）**：安全系数、冲刷深度可不填；新增 `survey.soft_foundation_status`；响应新增 `result.gates_not_checked`、`result.indicator_sources`、`mode_responses.*.basis`，`/meta` 新增 `indicator_source_labels`；新增警告码 `input_missing_no_gate`；D3由险情记录触发时改写门控文字。1.0.0 的请求无需修改，完整输入下的结果不变（D3门控文字除外）。
  - **1.0.0（2026-10-22）**：首个版本。
- 模型代码如有更新：替换 `levee_eval/model/` 中的文件 → 更新 `tests/test_api.py` 中的sha256 → 运行 `tools/build_fixtures.py` 重建基准并核对差异 → 运行 `tools/gen_docs.py` → 全部测试通过后提升版本号。
