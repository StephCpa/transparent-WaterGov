# 第6章数字孪生平台推演模块初步方案（草案，2026-10-17）

## 1 定位与目标

第1章的第三个关键科学问题要求地质建模、渗流计算、病害巡检与安全评价四环节闭环联动，并在多工况、多水位条件下实现可视化动态推演；绪论还引用了“正向预演风险形势、逆向推演工程安全运行限制条件”的要求。本方案为第6章平台设计一个推演模块：以统一的环境接口调用第4章渗流计算和第5章评价，在给定洪水过程和应对预案下滚动计算渗流场、巡检证据、安全等级与预警，并支持预案比选和限制条件反推。

| 功能 | 输入 | 输出 |
|---|---|---|
| F1 正向预演 | 水位过程（设计、历史或预报）、参数实现、预案 | 各断面逐时段的出逸梯度、等级范围、预警级别、证据与措施状态 |
| F2 预案比选 | 一组洪水情景与参数不确定性、若干预案 | 多目标指标表（确定C级场次、可能C级时长、代价、复核工作量、预警提前量）与Pareto前沿 |
| F3 逆向推演 | 断面、措施组合 | 达到“可能B、确定B、可能C、确定C”各门控的临界水位，用于预警水位的推演 |

边界：推演结果是辅助决策信息，不替代规范安全鉴定和现场防汛指挥；强化学习只作为可选的探索手段，不作为上线控制器。

## 2 借鉴HydroGym的设计

HydroGym（github.com/dynamicslab/hydrogym，MIT许可）的核心层与求解器无关，本方案借用其结构而非其流体环境。

| HydroGym做法 | 本方案对应设计 |
|---|---|
| `PDEBase`（状态、执行器、观测、目标）与`TransientSolver`（时间推进）分离 | 求解器适配契约`SeepageAdapter`：评价与推演不接触求解器内部 |
| `FlowEnv`的`reset/step`与动作子步`num_substeps` | 计算步1 h，决策间隔6 h |
| 执行器动态（`TAU`、`DampedActuator`） | 措施的建造或启动时间、建成后不可撤除 |
| 环境检查点与HuggingFace配置数据集 | 基准水位下的稳态初始场、带版本号的情景包 |
| 同一环境多级网格（coarse/medium/fine） | R0、R1、R2三级保真度适配器 |
| 标量奖励 | 输出目标向量并施加“不出现确定C级”约束，沿用第5章的多目标策略评价 |
| Docker统一环境 | 第4章求解器及其依赖的统一运行环境 |

已验证：`hydrogym_compat.py`把适配器包装为HydroGym的`PDEBase`/`FlowEnv`，在只装HydroGym核心（不装Firedrake）的环境中通过测试，可直接使用其Gymnasium工具链。

## 3 总体架构

| 层 | 职责 | 骨架文件 |
|---|---|---|
| 情景层 | 水位过程、预报误差、参数不确定性（渗透系数、出口土层孔隙比）、随机种子 | `runner.py`（`hydrograph`、`sample_scenarios`） |
| 求解器适配层 | 设定水位边界与措施，推进一步或求稳态，返回出逸面、测压管与出流 | `interfaces.py`、`adapters.py` |
| 措施层 | 措施库、启动/建造时间、代价、可撤除性 | `plans.py`（`CATALOGUE`、`Deployment`） |
| 观测与证据层 | 虚拟测压管、虚拟无人机巡检（含误报）、复核与证据状态 | `evidence.py`（`VirtualInspection`） |
| 评价层 | 第5章渗流门控、观测门控、等级范围、预警级别 | `evidence.py`（`assess`） |
| 环境层 | `reset/step`，记录逐时段结果，输出目标向量 | `env.py`（`RehearsalEnv`，可选Gymnasium包装） |
| 预案层 | 预案即策略函数，输入观测与孪生预测，输出措施指令 | `plans.py`（`PLANS`） |
| 评估与发布层 | 批量运行、汇总、Pareto、逆向推演，结果写入平台 | `runner.py`、`demo.py` |

## 4 求解器适配契约

```python
class SeepageAdapter(Protocol):
    fidelity: str                 # "R0" | "R1" | "R2"
    transient: bool               # False 时每步按当前边界求稳态（准稳态）
    supported_measures: tuple     # 可表达的措施类型
    sections: tuple               # 评价单元编号
    def reset(scenario): ...
    def set_boundary(t, river_stage): ...
    def apply_measures(measures): ...
    def advance(dt) -> SeepageOutputs: ...
    def steady(river_stage, measures=None) -> SeepageOutputs: ...
```

`SeepageOutputs`包含：时刻、水位、出逸面列表（编号、所属评价单元、法向向上出逸梯度、长度或面积、土层、出口层厚度、盖重附加水头）、测压管水头、出流量、梯度大于0.825的范围。出逸面按式（4-43）提取并配准到桩号区间，等级换算沿用第5章（$i_{cr}\in[0.825,1.03125]$，风险比取区间）。

三级保真度：

| 级别 | 内容 | 现状 |
|---|---|---|
| R0 | 第4章（1028版）数值的准稳态查表（表4-10、表4-12及4.5.2～4.5.3节，26.23～33.89 m五个水位，33.89 m为洪水位）。断面Ⅰ、Ⅱ的出逸梯度只有30.00 m和33.89 m两点（28.00 m及以下无向上出逸），按分段线性插值；三维梯度不小于0.825的Ⅱ、Ⅲ级面积和出流有五个水位 | 已实现；不能表达措施 |
| R1 | 一维承压层加背水侧盖层模型，可表达减压井、反滤围井、压渗平台、蓄水反压 | 已实现；合成参数，未率定 |
| R2 | 第4章二维、三维有限体积模型 | 待第4章代码 |

准稳态的依据：第4章三维模型在恒定水位下6 h时出流仅比第30天高0.282%，二维第30天与稳态的最大水头差为3.4×10⁻⁵ m。对以天计的洪水涨落，可先按准稳态运行R2，并预先计算一组水位（例如28.5～33.0 m每0.25 m）的稳态场用于快速筛选；涉及措施的组合需在线重算，排名靠前的预案再用瞬态复核。

需要第4章提供的对接清单：

1. 程序入口与依赖（语言、求解器库、能否在Linux无界面运行）；
2. 输入文件格式（地质模型映射、网格、材料参数），以及以程序方式设定临湖水位和背水侧边界的方法；
3. 稳态与瞬态的调用方式、单次求解耗时（二维1000×256、三维75×75×75）及并行方式；
4. 渗出面迭代的收敛设置；
5. 出逸面提取（式4-43）输出的字段：坐标、面积、法向梯度、所在土层；
6. 潜在通道回溯（式4-45）的接口与出口分级；
7. 各土层的土粒比重和孔隙比（取得后可把C1的区间收窄为确定值）；
8. 重启与检查点机制；
9. 计算坐标与桩号、堤轴版本的转换关系。

## 5 措施库与预案

| 措施 | R1中的表达 | 启动/建造时间 | 代价（相对占位值） | 可撤除 |
|---|---|---|---|---|
| 减压井抽排 | 背水坡脚汇项 | 0.25 d | 运行1.0/d | 是 |
| 反滤围井（养水盆） | 出口区抬高尾水位1.5 m | 0.25 d | 一次2.0，运行0.2/d | 否 |
| 压渗平台（盖重） | 出口区附加盖重水头，提高抗渗比降 | 1.0 d | 一次8.0 | 否 |
| 蓄水反压（垸内抬高水位） | 背水侧整体抬高尾水位1.0 m | 0.5 d | 运行1.5/d（淹没损失） | 是 |

代价为占位值，须按当地定额替换后才能用于比选结论。R2中的措施表达需与第4章边界条件对应：减压井为汇项或定水头井，围井和蓄水反压为出口区或背水侧的水头边界，压渗平台改变出口抗力（盖重）与渗出面位置。

预案即策略函数：

| 预案 | 规则 |
|---|---|
| P0 仅巡查 | 不采取措施 |
| P1 水位分级响应 | 水位达到警戒水位开减压井，达到保证水位加反滤围井 |
| P2 测压管反馈 | 按坡脚测压管估计的风险比上界比例开启减压井，风险比上界不低于0.95时加反滤围井 |
| P3 预报前瞻 | 用孪生模型对12 h水位预报求稳态，选出预测风险比上界不超过0.9的最省措施组合 |
| P4 蓄水反压优先 | 风险比上界不低于0.8时蓄水反压 |

P3体现了“以虚促实”：平台在每个决策时刻调用同一适配器预演未来状态，再据此选择措施。

## 6 观测与证据

- 虚拟测压管：在适配器给出的水头上加噪声（标准差0.03 m）。
- 虚拟无人机巡检：每日两次飞行（02:00、14:00），真实管涌（风险比按真实孔隙比计不低于1.0）按检出概率（夜间0.85、白天0.60）产生候选，误报按泊松过程产生（每段每次飞行夜间0.15个、白天1.0个）；复核延迟2 h，复核正确率0.95，存疑点在下一次飞行时复查；巡检覆盖超过24 h视为过期。
- 证据状态沿用第5章表5-12：候选只放宽等级上限，确认事件触发观测门控，误报区不视为已检查无异常。

上述检出率和误报率是占位参数。现有现场资料只有第5章的9个白天候选（113张图像，全部误报），没有真实管涌的检出率，取得夜间巡检和人工管涌试验数据后再标定。

## 7 评价与指标

逐时段评价：按出逸面的风险比区间判定渗流门控（确定或可能达到0.8、1.0），叠加观测门控和覆盖状态，输出等级下限、上限和预警级别（第5章表5-17）。其余27项静态指标在本草案中未接入，计划在M1阶段通过交付的规则链和断面指标台账接入。

逐场指标：确定C级时长与场次、可能C级时长、B级及以上时长、真实风险比不低于1.0的时长（仅推演可见，用于检验漏报）、最大风险比上界、预警提前量（首次二级及以上预警到首次确定C级的时间）、措施代价、复核任务数与误报复核数。

预案选择沿用第5章5.3.4节：先施加“无确定C级”约束，再在（确定C级场次、可能C级时长、代价、复核任务）上取Pareto前沿，代价与安全的折中单独报告。

## 9 平台集成

- 服务接口（JSON）：`/scenarios`（情景包列表与版本）、`/rehearsal/runs`（提交推演任务，异步）、`/rehearsal/runs/{id}/timeline`（逐时段、逐断面结果）、`/rehearsal/runs/{id}/fields/{t}`（场快照，供三维渲染）、`/rehearsal/compare`（多预案比选与Pareto）、`/rehearsal/limits`（逆向推演）。
- 记录格式在现有离线接口示例（`schema_version: example-0.1`）上扩展推演字段：`scenario_id`、`plan_id`、`t`、`fidelity`、`adapter_version`、`seed`，每条结论保留来源与版本，溯源方式同第5章。
- 三维场景：出逸面按等级随时间着色，潜在通道按Ⅰ～Ⅲ级显示，时间轴叠加水位、等级范围与预警，预案比选面板展示多目标表与Pareto前沿。

## 12 风险与待定事项

1. 三维计算耗时：批量推演依赖准稳态和水位库，措施组合多时需降阶或代理模型。
2. 渗出面非线性：措施改变渗出面位置时不能简单叠加，需在线重算。
3. 措施与巡检参数缺少标定数据，比选结论只能作相对比较。
4. 代价为占位值，需按定额替换。
5. 示范工程命名：第1章、第6章写长春垸，第4章与第5章为匿名，统稿时需统一。
6. 强化学习仅通过Gymnasium/HydroGym接口作为可选探索；原型试验表明，在单一措施的扩散问题上，调好的规则已接近学习策略，选择仍应采用多目标评价并保留物理门控底线。
